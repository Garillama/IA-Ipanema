# Preparar una tienda para trabajo continuo

Propuesta de operación posterior al discovery, 2026-11-08.

1. Registrar ruta local, dominio y theme_id en un perfil por tienda. Confirmar el tema de cada URL y la instalación que entrega sus assets; no usar un nombre de carpeta como identidad remota.
2. Leer instrucciones aplicables, Git status y estado remoto autorizado. Conservar diferencias y datos del comerciante antes de una sincronización; no ejecutar pull automático ni iniciar watch para «ver qué pasa».
3. Identificar generación: .tpl/schema + JSON/sections/blocks es seccionable; no aplicar instrucciones FTP de temas clásicos. Verificar versión/fork por lectura remota y registrar fecha.
4. Inventariar componentes/tokens y valores efectivos. Definir identidad de marca, contenido y asignación de templates con funciones nativas antes de custom code.
5. Tomar línea base de home, categoría, PDP, búsqueda, carrito vacío y páginas públicas reales, con HTML, DOM, recursos, seis anchos y accesibilidad. Mantener password/staging/producción separados.
6. Revisar SEO de contenido, navegación y endpoints sin sesión antes de lanzamiento. No quitar protección de tienda dentro de una auditoría.
7. Preparar cambios pequeños con diff, prueba proporcional y registro de consumidor compartido. Revisar datos remotos otra vez antes de enviar; publicación solo dentro de autorización explícita.

La copia de settings entre tiendas necesita remapear medios/productos/menús. La estructura reusable no transporta permisos, credenciales ni licencias del tema. [Estrategia multitienda](../08-design-system/multi-store-strategy.md).
